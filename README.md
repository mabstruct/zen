# ZEN

## What it is

ZEN is a personal knowledge system built around one question: how do I keep notes, documents and what I have learned in one place that Claude can search, cite and keep consistent? Its four capabilities, from the spec: find by meaning, not only keywords (qmd); read what was found with a path back to the original; stay clean — contradictions are marked, never overwritten (the wiki); and trace every document to a captured copy with a date. Claude follows a Brain-First rulebook in `CLAUDE.md`.

## Layout

```
zen/
├── CLAUDE.md          Brain-First rulebook for Claude
├── .claude/skills/    the six Claude Code skills
├── workspace-template/  seed for a new workspace: templates, wiki SCHEMA, starter clusters
├── vault/             YOUR WORKSPACE — a separate (private) git repo, not tracked here
│   ├── 00_inbox/      drop zone for unfiled items
│   ├── 1x_*/          clusters: notes, companions, and _originals/ (the source files)
│   ├── 90_wiki/       Claude-maintained wiki (SCHEMA.md, LOG.md, INDEX.md, pages)
│   ├── INDEX.md       generated by zen-index
│   └── _meta/         generated by zen-index
├── tools/             uv Python package: zen-index, zen-intake, zen-ask-prep, zen-move, zen-plan, zen-sync-schema
├── scripts/           ws-init.sh, ws-sync-schema.sh, qmd-setup.sh, qmd-refresh.sh
└── docs/              spec, plan, references, tests, benchmarks
```

## Setup on a fresh clone

Prerequisites: macOS, `uv`, Node >= 20 with npm.

```
(cd tools && uv sync)
./scripts/ws-init.sh https://github.com/<you>/<your-workspace>.git   # or no argument: scaffold an empty one
./scripts/qmd-setup.sh
```

`ws-init.sh` puts your workspace at `vault/` — either by cloning your workspace repo or by scaffolding a fresh one from `workspace-template/` — and builds the first index. `qmd-setup.sh` installs `@tobilu/qmd` globally and downloads about 2 GB of models, so the first run takes about 10 minutes.

## Workspace vs. system

This repo is the **system**: tools, rulebook, skills, docs, and the workspace template. It holds no knowledge. Your **workspace** — notes, originals, the wiki — lives in `vault/`, which is its own git repo (keep it private: it will contain your documents and the full text of what you ingest). `vault/` is git-ignored here. The wiki's rules (`90_wiki/SCHEMA.md`) are seeded from the template; after pulling a change to the template's SCHEMA, run `./scripts/ws-sync-schema.sh` (`--check` shows drift without changing anything) and commit the workspace.

## Daily use

In a Claude Code session rooted in `zen/`:

- `/zen-intake` files a document, URL, arXiv paper or DOI (or the whole inbox) as original plus markdown companion.
- `/zen-note` captures a note into the right cluster.
- `/zen-ask` answers a question from the vault, wiki first — three model calls: `zen-ask-prep` (indexes + search hits in one call), one file, the answer.
- `/zen-ingest` condenses new or changed sources into the wiki and marks conflicts; routes each file to the standard or deep ingester agent (model baseline in `CLAUDE.md`).
- `/zen-index` regenerates the index and shows vault health.
- `/zen-move` re-files a note or companion into another cluster, or renames a whole cluster, and rewrites every reference.

Brain-First ladder: Claude reads `vault/INDEX.md` first, then the wiki, then runs qmd search, then opens exactly one file — never scanning folders and never opening `_originals/`.
