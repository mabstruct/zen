# zen-ui v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local and Docker-deployable web app. It shows every ZEN wiki page and source as a force-directed graph (colour = kind, size = confidence plus hubs) and opens any node in a reader whose links navigate the app, with a trail and shareable URLs. It is read-only.

**Architecture:** A Python change adds `confidence` and `conflicts` to `_meta/map.json`. A Node snapshot script (`ui/scripts/snapshot.ts`) turns `map.json` plus the vault's markdown into `ui/public/data/graph.json` and `ui/public/data/pages/<vault path>`. A React app reads those static files through one module (`ui/src/data.ts`) and renders an SVG graph laid out by `d3-force` and a markdown reader. `scripts/ui-publish.sh` re-indexes, snapshots, and builds an nginx Docker image from `ui/` alone.

**Tech Stack:** React 19, Vite 7, Tailwind 4 (`@tailwindcss/vite`), lucide-react, TypeScript (erasable syntax only, so Node runs `.ts` scripts natively), d3-force / d3-zoom / d3-drag / d3-selection, marked, DOMPurify, vitest + @testing-library/react + jsdom, Playwright (one smoke test), Docker (`node:24-alpine` build stage, `nginx:alpine` serve stage). Python ≥ 3.12 via `uv` in `tools/` for Task 1.

**Spec:** `docs/superpowers/specs/2026-10-19-zen-ui-design.md`. Read it first; this plan argues from it. Section numbers below (§5.2 …) refer to it.

## Global Constraints

- Nothing in `ui/` or `scripts/ui-publish.sh` writes to `vault/`. Only `zen-index` writes there, and it writes `INDEX.md` and `_meta/map.json`.
- Nothing under `_originals/` is ever copied, served, or put in the image. A link to one renders as text with "(original not published)".
- `map.json` decides node and edge membership. The markdown is read only for page copies and conflict blocks.
- Node kinds are exactly `topic | entity | synthesis | source`, from map types `wiki-topic | wiki-entity | wiki-synthesis`, and from `companion | note` in a cluster matching `^1\d_`. Excluded: `wiki-meta`, `wiki-source` (merged into its source node), `original`, `tag`, `00_inbox/`, `01_daily/`, `02_templates/`, the root `INDEX.md`.
- Edge kinds are exactly `cites | links | conflict`.
- Data access goes only through `ui/src/data.ts` (§3, v2 swaps it for an API).
- Hash routes are `#/` and `#/p/<vault path>`, where the path is the page's vault-relative path with each segment `encodeURIComponent`-ed.
- Laptop layout only, in the dark visual style of the CONSTRUCT site (`mabstruct-site/website/mabstruct-presence`).
- Shell commands run from `/Users/mab/dev/mabstruct/zen`; `npm` commands from `ui/`; `uv run` commands from `tools/`. Branch `zen-ui`. Commit footer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A companion's extracted text containing raw HTML (`<script>`, `<img onerror>`) must render inert. Web articles are companions, and the app is public. — test in Task 4.
2. Links written as `my%20note.md`, `<my note.md>`, or with a `#fragment` must resolve to the same node as the plain path. — test in Task 4.
3. A stale `map.json` naming a file that is gone from disk must drop that node, its edges, and its page with one warning line, not abort the snapshot. — test in Task 3.
4. A shared URL to a path not in this snapshot (`#/p/nope.md`) must show the graph and a "not in this snapshot" reader, not a blank screen. — test in Task 6.
5. Find-by-title must ignore case and diacritics, so "jurgen" finds "Jürgen Schmidhuber". — test in Task 5.

**Interfaces:**
- Produces, in `ui/src/types.ts`:
  ```ts
  export type Kind = 'topic' | 'entity' | 'synthesis' | 'source'
  export type Confidence = 'low' | 'medium' | 'high' | null
  export interface GNode { id: string; title: string; kind: Kind; clusters: string[]; confidence: Confidence;
    conflicts: string[]; updated: string | null; wiki: string | null; vault: string | null; ingested: boolean; inDegree: number }
  export interface GEdge { from: string; to: string; kind: 'cites' | 'links' | 'conflict'; conflict?: string; pages?: string[] }
  export interface Graph { generated: string; nodes: GNode[]; edges: GEdge[] }
  export interface MapNode { id: string; path: string | null; title: string; type: string; cluster: string | null; updated: string | null; confidence: Confidence; conflicts: string[] }
  export interface ZenMap { generated: string; nodes: MapNode[]; edges: { from: string; to: string; kind: string }[] }
  ```
  Field meanings:
  - Wiki node: `id = wiki = <90_wiki path>`, `vault = null`, `ingested = true`.
  - Source node: `id = vault = <vault path>`, and `wiki` is its `90_wiki/sources/*` page or null. `ingested = wiki !== null`.
  - Source node's `confidence` is null.
  - A wiki node's `clusters` are the sorted unique clusters of the source nodes it cites. A source node's `clusters` is `[its cluster]`.
  - `conflicts` comes from the node's own page: the wiki page for a wiki node, the `wiki` page for a source node.
- Produces, in `ui/scripts/graph.ts`:
  - `buildGraph(map: ZenMap, readText: (path: string) => string | null): { graph: Graph; warnings: string[] }`. `readText` returns null for a missing file, and such a node is dropped with the warning `missing on disk: <path>`.
  - In `ui/src/graph.ts`: `owners(graph: Graph): Map<string, string>`, mapping every `wiki` and `vault` path to its node id, and `resolvePath(from: string, href: string): string` (contract in Task 4). Both are used by the snapshot and the app.
  - `parseConflicts(pagePath: string, text: string): { id: string; a: string | null; b: string | null }[]`, covering open blocks only. `a` and `b` are the first `sources/` link on the block's `> A:` and `> B:` lines, resolved against `pagePath` to a vault path.
- Edge rule: map every map edge of kind `link` or `wiki` through `owners`. Then:
  - Drop it if either end is unmapped, if both ends are the same node, or if it comes from a `wiki-meta` page.
  - wiki → source becomes `cites` (from the wiki node).
  - Any other pair becomes `links`.
  - Then add one `conflict` edge per open block whose `a` and `b` both map to source nodes, with `conflict = id` and `pages` = every page carrying that id.
  - Deduplicate on `(from, to, kind)` (for `conflict`, on `(sorted ends, id)`).
  - `inDegree` counts incoming `cites` and `links` after deduplication.

### Task 4: markdown rendering and link resolution (§5.3 Reader)

**Files:**
- Create: `ui/src/markdown.ts`
- Modify: `ui/src/graph.ts` (only if `resolvePath` from Task 2 fails the cases below)
- Test: `ui/src/markdown.test.ts`

**Interfaces:**
- Produces:
  - `resolvePath(from: string, href: string): string`. It strips `<…>`, the `#fragment` and `?query`, decodes `%xx`, and returns a posix-normalised vault path.
  - `type LinkTarget = { type: 'node'; id: string; path: string } | { type: 'original' } | { type: 'external'; href: string } | { type: 'text' }`
  - `resolveHref(from: string, href: string, owners: Map<string, string>): LinkTarget`. The rules are tried in order:
    1. `^https?:` → external.
    2. A resolved path containing `/_originals/` or starting with `_originals/` → original.
    3. A path in `owners` → node.
    4. Anything else → text.
  - `stripFrontmatter(md: string): string`.
  - `splitCompanion(md: string): { summary: string; extracted: string | null }`. It splits at the `## Extracted text` heading. `summary` is everything before it without frontmatter, and `extracted` is the rest after the heading, or null.
  - `renderMarkdown(md: string, from: string, owners: Map<string, string>): string`. It produces sanitised HTML via `marked` and then `DOMPurify.sanitize`. Links are rendered as follows:
    - node → `<a href="#/p/<encoded path>" data-zen-path="<path>">`
    - external → `<a href target="_blank" rel="noopener noreferrer">`
    - original → `<span class="zen-original">text (original not published)</span>`
    - text → `<span class="zen-deadlink">text</span>`

    A blockquote whose first line matches `[!conflict] (#c-\d+) — (open|resolved)` gets `class="zen-conflict zen-conflict--<state>"`.
  - `toHash(path: string): string` and `parseHash(hash: string): { path: string | null }`.

### Task 5: graph view (§5.3 Graph view)

**Files:**
- Create: `ui/src/graphView/style.ts`, `ui/src/graphView/GraphView.tsx`
- Test: `ui/src/graphView/style.test.ts`, `ui/src/graphView/GraphView.test.tsx`

**Interfaces:**
- Consumes: `Graph`, `GNode` (Task 2).
- Produces:
  - `nodeRadius(n: GNode): number`. For sources it is `7`. For wiki pages it is a base of `{ low: 6, medium: 10, high: 14 }` (null counts as low) plus `Math.min(3.5, 1.5 * Math.log2(1 + n.inDegree))`.
  - `nodeColour(n: GNode, mode: 'kind' | 'cluster'): string`. In kind mode it uses one fixed colour per kind. In cluster mode it hashes `clusters[0]` into a fixed palette of 8.
  - `neighbourhood(g: Graph, id: string): Set<string>`, the node plus its direct neighbours over all edge kinds.
  - `visible(g: Graph, hidden: Set<Kind>): Graph`, which drops the hidden kinds and their edges.
  - `findByTitle(nodes: GNode[], q: string): GNode | null`. It folds case and diacritics with `NFD` and strips `\p{M}`. It prefers a title that starts with the query, then the shortest title containing it.
  - `<GraphView graph={Graph} selected={string | null} onSelect={(id: string) => void} />`. It renders an SVG with:
    - one `<g data-node-id>` per node, whose circle uses `nodeRadius`; sources are drawn as a rounded square;
    - `cites` and `links` edges as thin neutral lines, and `conflict` edges in red with `stroke-dasharray`;
    - a hover that dims everything outside `neighbourhood`;

    2. runs `(cd ui && npm ci && npm run snapshot)`;
    3. runs `docker build -t zen-ui:<tag> ui/`;

  - The Dockerfile has two stages:
    - `FROM node:24-alpine AS build`, which runs `WORKDIR /app`, `COPY package*.json ./`, `RUN npm ci`, `COPY . .`, `RUN npx vite build`;
    - `FROM nginx:alpine`, which runs `COPY nginx.conf /etc/nginx/conf.d/default.conf` and `COPY --from=build /app/dist /usr/share/nginx/html`.
  - nginx serves `try_files $uri $uri/ /index.html`, sets `charset utf-8`, and gives `.md` files `text/markdown`.
  - `.dockerignore` excludes `node_modules`, `test`, `e2e`, `dist`, `test-results`, `playwright-report` and `*.test.*`.
