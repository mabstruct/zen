# ZEN — Design Spec v1

Date: 2026-10-14. Status: approved in brainstorming, pending written review.
Baseline: [The Node AI, "Der echte Weg zum Second Brain"](../../references/baseline-video-the-node-ai-second-brain.md). ZEN follows its shape; deviations are marked **Deviation**.

## 1. Founding question and capabilities

> How does collected knowledge become a system I can trust, instead of a growing junk pile?

Two halves: **findability** (find it even without the exact word) and **trust** (duplicates, contradictions, stale states surface instead of lying around).

v1 capabilities, each verifiable:

| # | Capability | Home |
|---|-----------|------|
| 1 | Find relevant information in seconds, by meaning, not only by keyword | qmd |
| 2 | Read what was found in the same session, with a path back to the original document | companions + `_originals/` |
| 3 | Stay clean: contradictions and duplicates are marked, knowledge is condensed, nothing is silently overwritten | wiki |
| 4 | Every document in the vault is traceable to a captured copy with a date, and to its live URL if it has one | source model |

Not in v1: overview/graph (the map file is produced so a later app has nothing to invent).

## 2. Decisions taken in brainstorming

- Brand-new vault under `zen/vault/`. Existing corpora (mabstruct-workspace, CONSTRUCT) are imported later by running intake on them; no migration tooling.
- Markdown is the only truth. Originals (PDF, DOCX, PPTX, XLSX, HTML, images) live in the vault next to a markdown **companion**; index and search read only markdown.
- Claude Code is the interface for this phase. The vault stays editor-neutral.
- Two-stage intake: deterministic intake (free), on-demand wiki ingest (the only place tokens are spent besides answering).
- Stack: Python `uv` project for the deterministic tools; qmd as the installed search building block; thin Claude Code skills carry the rules.
- Fully local: index, search, vault. Only excerpts chosen by the ladder, and files handed to wiki ingest, reach the model.
- Colour rule from the video: minimise "purple". AI is used in exactly two places — answering (`/zen-ask`) and wiki ingest.

## 4. File conventions

Every `.md` in the vault starts with YAML frontmatter.

Common fields:

```yaml
title: Attention Is All You Need
type: note | companion | daily | wiki-source | wiki-topic | wiki-entity | wiki-synthesis
created: 2026-10-14T18:02:11+02:00     # set by the tool or skill that creates the file
updated: 2026-10-14T18:02:11+02:00     # set by any tool/skill that writes the file
ingested: 2026-10-15T09:10:00+02:00    # last wiki ingest of this file; absent = never
tags: [transformers, attention]
```

Companion-only fields:

```yaml
source:
  kind: file | url | arxiv | doi
  url: https://arxiv.org/abs/1706.03762        # when it came from the web
  local: _originals/1706.03762.pdf             # snapshot path relative to the cluster; absent if none
  hash: sha256:…                               # of the snapshot, for dedupe
  captured: 2026-10-14T18:02:11+02:00          # when text was extracted
snapshot: ok | missing                         # missing = URL only, fetch failed
extraction: ok | failed | none                 # none = images and other opaque types
```

Companion body:

```markdown
# <title>

## Summary
<empty until wiki ingest writes it, or you do>

## Extracted text
<markitdown output>
```

The heading repeats `title` so readers and search tools that take the first heading show the right name.

Rules:
- Cluster is derived from the path, never stored in frontmatter.
- One note, one place. Cross-reference with links, never by filing twice.
- Links are standard relative markdown links `[text](../11_research/foo.md)`. The indexer also parses `[[wikilinks]]` so an Obsidian phase later costs nothing.
- All timestamps ISO 8601 with offset. Tools write them; the indexer never writes into the vault except its two outputs. For hand-edited notes without `updated`, the indexer reports file mtime.
- Filenames are slugs: lowercase, hyphens, ASCII; arXiv ids keep their id as the slug.

## 5. Indexer — `zen-index` (deterministic, no AI, no network)

Walks `vault/`, parses frontmatter, links and tags of every `.md`; never opens originals. Regenerates both outputs from scratch each run; idempotent; runs in seconds.

**`vault/INDEX.md`** — the catalog Claude reads first. Target size: a few hundred lines even at thousands of notes.
- Header: generated timestamp, totals (notes, companions, originals, wiki pages, open conflicts).
- One section per cluster: description from `_cluster.md` (or folder name), counts, then one line per *important* file, newest `updated` first: `- [title](path) — first line of Summary · tags · updated YYYY-MM-DD`. Important = non-empty `## Summary`, or inbound links ≥ 3, or tag `pinned`. Non-important files are counted, not listed.
- `## Wiki`: pages grouped by type, one line each, from `90_wiki/INDEX.md`.
- `## Health`: inbox items older than 7 days; companions with `snapshot: missing` or `extraction: failed`; orphans (no inbound and no outbound links); broken links; duplicate titles; files never ingested; files with `updated` > `ingested` ("wiki behind" — the ingest queue); open conflicts (ids and pages).

**`vault/_meta/map.json`**:

```json
{"generated": "...", "nodes": [{"id","path","title","type","cluster","tags","size","created","updated","captured","ingested"}],
 "edges": [{"from","to","kind": "link|tag|source|wiki"}]}
```

No consumer in v1. Exists so the later app phase only displays.

CLI: `zen-index [--vault PATH] [--check]`. `--check` exits non-zero when any vault file is newer than `INDEX.md`; skills use it before answering.

## 6. Search — qmd (building block, adopted as-is)

- One qmd collection over `vault/`, ignoring `_originals/`, `_meta/` and `02_templates/`.
- Modes used: keyword, semantic (`vsearch`), hybrid with rerank (`query`). `/zen-ask` uses hybrid.
- Models are local, downloaded once; no API cost; works offline. Re-index is triggered by the intake, ingest and index skills.
- qmd is the only place embeddings exist. ZEN's own code never embeds and keeps no vector store.
- Exact install command, CLI names and ignore mechanism are verified during planning, not assumed here.

## 7. Rulebook — `zen/CLAUDE.md`

Brain-First ladder, applied on every knowledge question:

1. Read `vault/INDEX.md`. If the source is listed, open exactly that file.
2. Check `90_wiki/` via its `INDEX.md`. Prefer a wiki page over raw sources — the knowledge may already be condensed.
3. Only then `qmd query`. Judge candidates by their snippets without opening files.
4. Open exactly ONE file — the best — and read only the relevant section. In a companion, read `## Summary` first; `## Extracted text` only if the summary does not answer.
5. Answer, citing file paths. Never scan folders. Never open originals.

`zen-ask-prep "<question>"` (v1.1) performs steps 0–3 in one deterministic call — stale check with re-index, `INDEX.md` without its Health section, wiki `INDEX.md`, top qmd hits with snippets — so a question costs three model calls (prep, one file, answer) instead of six. The ladder's order and the one-file rule are unchanged; qmd failure degrades to the first two rungs with a one-line notice.

Further rules: never hand-edit `90_wiki/`, `INDEX.md`, `_meta/`; after writing to the vault run `zen-index` and qmd re-index; if `zen-index --check` fails, re-index before answering; wiki work only through `/zen-ingest`; the human decides every conflict.

**Known extension (not v1):** let step 3 return qmd chunk snippets instead of file-level hits for long PDFs.

## 8. Intake — `zen-intake` (deterministic, no AI)

Input: a file or folder path, a URL, an arXiv id/URL, a DOI, or nothing (= everything in `00_inbox/`). A folder = its files, non-recursive; subfolders of `00_inbox/` are ignored. Option `--cluster <id>`.

Per item:
1. **Resolve** the source kind. arXiv → fetch PDF; URL → fetch page; DOI → resolve to a freely available PDF, else the landing page; file → use as is.
2. **Dedupe** by SHA-256 of the original. Already in the vault → report and skip.
3. **Extract** with `markitdown` (PDF, DOCX, PPTX, XLSX, HTML, TXT, MD). Images → companion with metadata only, `extraction: none`. Any failure → companion still written, flagged; nothing is dropped silently.
4. **Cluster**: `--cluster`, else a `cluster:` key in a raw note's frontmatter, else the item stays in `00_inbox/` and appears in Health. Code never guesses.
5. **Write**: original → `<cluster>/_originals/<slug>.<ext>`; companion → `<cluster>/<slug>.md` per section 4; `title` from document metadata, else first heading, else filename.
6. Raw markdown notes in the inbox: frontmatter normalised, `type: note`, moved; no extraction.

Afterwards: `zen-index`, qmd re-index, one-screen report (filed / skipped-duplicate / left-in-inbox / failed).

Guarantees: idempotent; never modifies existing notes or companions; never deletes; all effects visible in the report and `git status`.

**Deviation:** the baseline's step 1 was a manual vault cleanup. ZEN automates the mechanical part and leaves the one judgement — which cluster — with the human.

## 9. Wiki — `90_wiki/` (Claude-maintained)

Hard rule: the human never edits it. Only `/zen-ingest` writes. Human input is decisions.

```
90_wiki/
├── SCHEMA.md     Claude's work instruction: page types, rules, conflict format. Read before every ingest.
├── INDEX.md      wiki page catalog, one line per page, maintained by ingest
├── LOG.md        append-only run log
├── sources/      one page per ingested file: its claims in 10–20 lines, link back to the file
├── topics/       one page per concept, condensed across sources
├── entities/     people, projects, tools, organisations
└── syntheses/    cross-topic pages, written when ≥ 3 sources converge on a theme
```

Page frontmatter: `type: wiki-*`, `created`, `updated`, `sources: [vault paths]`, `confidence: low|medium|high`.

**Ingest, one file per run, fresh context per file:**
1. Read `SCHEMA.md` and wiki `INDEX.md`.
2. Read the input companion or note.
3. From the wiki index, select the pages this file touches; open only those.
4. Write/update: a `sources/` page; affected `topics/` and `entities/`; links in both directions; a `syntheses/` page if the threshold is met.
5. For every claim written, check the target page for an existing statement it contradicts. **Mark, never overwrite.**
6. If the input's `## Summary` is empty, write it. Stamp `ingested` and `updated` on the input.
7. Append to `LOG.md`: timestamp, input path, pages created/updated, conflict ids raised. Update wiki `INDEX.md`.

**Conflict block** (identical id wherever the conflict appears):

```markdown
> [!conflict] #c-0042 — open
> A: "<claim>" — sources/paper-x.md (captured 2026-03-01)
> B: "<claim>" — sources/notes-y.md (captured 2026-10-14)
> Decision: pending
```

Resolution is human: fix the source note, or `/zen-ingest --resolve c-0042 "<decision>"`, which rewrites every block for that id to `resolved`, records the decision in `LOG.md`, and updates the affected pages. Open conflicts are listed in the vault `INDEX.md` Health section. Ids are sequential, allocated from `LOG.md`.

Bulk: `/zen-ingest` with no arguments works the "wiki behind" queue from the vault index, one fresh subagent per file, stopping on first error.

## 10. Skills (`zen/.claude/skills/`)

Thin: they call tools and carry rules; no logic lives in a prompt that could live in code.

| Skill | Does |
|-------|------|
| `/zen-ask <question>` | runs `zen-index --check`; walks the ladder; answers with paths |
| `/zen-intake [path\|url\|arxiv\|doi] [--cluster id]` | `zen-intake` → `zen-index` → qmd re-index → report |
| `/zen-ingest [files…] \| --resolve <id> "<decision>"` | wiki ingest per section 9; no args = queue |
| `/zen-index` | `zen-index` + qmd re-index; prints Health |
| `/zen-note <title> [--cluster id]` | new note from template with timestamps, filed |

## 11. Testing and success criteria

**Tool tests (pytest, `tools/tests/`)**, real filesystem, fixture vaults, no mocks:
- Indexer: fixture vault → INDEX.md and map.json equal golden files; Health catches orphans, broken links, missing snapshots, never-ingested, wiki-behind, open conflicts; `--check` detects staleness.
- Intake: PDF/DOCX/HTML/MD fixtures → expected companions; duplicate hash skipped; failed extraction yields a flagged companion; re-run is a no-op; existing files untouched.
- Frontmatter round-trips; timestamps ISO 8601 with offset.

**Trust test (manual, once):** a note with three planted contradictions against existing wiki content plus one harmless confirming statement. Pass = all three marked with a shared id on every affected page, the harmless one merged, nothing overwritten, `LOG.md` shows the run.

**Benchmark (manual, repeatable):** after the first real import, five real questions. Each run via `/zen-ask` and once in a plain Claude session without ZEN; tokens, time, correctness recorded in `docs/benchmarks/`. No numeric target beyond "fewer tokens, still correct".

**Done:** tool tests green; trust test passed; one benchmark recorded; `/zen-ask` used on real questions for several days and still preferred over manual search.

## 12. Non-goals for v1

No graph or web app. No OCR. No automatic cluster assignment. No Obsidian plugin or `.obsidian/` config. No cloud sync. No chunk-level retrieval in `/zen-ask`. No migration tooling for mabstruct-workspace or CONSTRUCT.

### v1.1 backlog

Known deviations from this spec in v1:

- DOI resolution fetches the landing page only; there is no free-PDF lookup.
- An explicit `.md` path given to intake from outside the inbox is treated as an original with a companion rather than filed as a note.
- `zen-intake vault/00_inbox` as a folder spec runs the file path, not inbox mode; use `zen-intake` with no arguments.
- arXiv companions are titled by their id when the PDF carries no metadata title; `/zen-ingest` sets the real title on first ingest.
- A URL whose fetch failed is reported `duplicate` on re-run (against its `snapshot: missing` companion); use `zen-intake --retry-missing`.
- Deleting or renaming a vault file does not mark the index stale (`--check` compares file mtimes only).

Planned additions:

- **Done in v1.1: `zen-move <vault-path> --cluster <id>`, and `zen-move --rename-cluster <old> <new>` for a whole cluster** (`tools/src/zen/move.py`, `/zen-move` skill) — re-cluster a document after a wrong filing decision. Deterministic, one atomic step: `git mv` the companion and its original together (`source.local` stays valid because it is cluster-relative); rewrite every inbound link in the vault (the scanner already knows them); patch the wiki source page's `sources:` entry and its back-link (and rename `sources/<stem>-<cluster>.md` if the collision rule had applied); regenerate the index; refresh qmd. Refuses if the target cluster does not exist or the move would leave a broken link. Does **not** bump `updated` (a move is not a content change and must not enter the wiki-behind queue); logs a `move` entry in `LOG.md`. This is the one tool other than `/zen-ingest` allowed to write under `90_wiki/`, limited to path rewrites — §7 and `SCHEMA.md` need that exception stated.
- **Done in v1.1:** `zen-intake --retry-missing` — re-fetch companions flagged `snapshot: missing` in place instead of reporting `duplicate`.
- **Done in v1.1:** `zen-intake --recapture <path>` (snapshot replaced in place, earlier version kept by the workspace git history, Summary cleared so re-ingest rewrites it) — deliberate re-capture of a changed web page as a new `captured` date on the same companion.
- arXiv title lookup via the arXiv API at intake (one extra fetch) so companions never carry a bare id as title.
- `/zen-ask` may read qmd chunk snippets instead of file-level hits for long PDFs (noted in §7).
- **Model selection per task.** v1 names no model anywhere: `/zen-ingest`'s per-file subagent inherits the session model, and the session model is whatever the user last picked. Two places spend tokens and they have different needs:
  - *Ingest* (condense, cross-link, detect contradictions) is judgment-heavy and runs unattended per file — it should default to the most capable model.
  - *Ask* (walk the ladder, read one file, answer) is small-context and interactive — the session's model is fine.
  - Intake, index and note need no model at all.

  **Done in v1.1**, with the baseline taken from `docs/benchmarks/2026-10-15-ingest-model-comparison.md` rather than "most capable for everything": two versioned project agents, `.claude/agents/zen-ingester.md` (mid-tier; routine first ingests) and `.claude/agents/zen-ingester-deep.md` (premium; extracted text > 50 KB, re-ingests, syntheses, or `--deep`). `/zen-ingest` applies that routing rule per file and dispatches the chosen agent; `--model <name>` overrides for one run; the model lives in the agent file's `model:` line for the project; `/zen-ask` runs on the session model. `CLAUDE.md` carries the "Model baseline" table. The SCHEMA text is still passed at dispatch (not baked into the agent) so it stays in sync with the workspace's `SCHEMA.md`. Still open: whether a cheaper model suffices for mechanical re-ingests of restamped files — measure before changing the rule.

Ask cost — from benchmark run 1 (`docs/benchmarks/BENCHMARK-2026-10-15.md`): `/zen-ask` spent 460k tokens against 267k for a plain session on the same question. The vault reads were cheap (~14k); the cost is the number of model calls — each re-reads ~88k tokens of standing session instructions. Priority item:

- **`zen-ask-prep "<question>"`** — one deterministic call that runs the stale check (re-indexing if needed), prints `vault/INDEX.md`, the wiki `INDEX.md` and the top qmd hits with snippets. The ladder becomes prep → open one file → answer: three calls instead of six. Keep the ladder's order and the "exactly one file" rule; only the number of round trips changes. Re-run the benchmark afterwards.
- Session overhead (the 88k) is Claude Code plugins/MCP servers, not ZEN; document a slim session profile for ZEN work.

Ingest time — from the 6-minute reference ingest (`docs/benchmarks/REFERENCE.md`): output generation and per-call latency dominate, not input size.

- Model routing per the comparison: mid-tier for routine first ingests, premium for long/numeric documents, re-ingests and syntheses (see model selection above).
- **Done in v1.1 (planned ingest):** planner + `zen-plan check` + parallel `zen-page-writer`s + `zen-plan finish`, for inputs over 20 KB of extracted text; not yet measured. Original idea — plan-then-parallel: a planner reads the source once and emits the page list with each page's claims and link targets (names fixed up front, contradiction check stays here because it is the only pass that sees everything); N writers then run concurrently with only their claims plus SCHEMA. Wall time ≈ planner + slowest writer instead of the sum.
- SCHEMA thresholds for entity pages (e.g. ≥ 3 claims or cited by ≥ 2 topics; otherwise a line on the topic page) to cut page count ~30 % and fragmentation.
- Background queue: `/zen-ingest` dispatches per-file subagents in the background and reports when done.
- Section-wise ingest only for very long documents (> ~60k tokens): split on `## ` headings, one subagent per section, one synthesis pass.
- `ws-sync-schema.sh`: copy `workspace-template/90_wiki/SCHEMA.md` into the workspace when the template's SCHEMA changes.

Robustness minors deferred by the final review (none affect correctness on current data):

- `frontmatter`: an empty frontmatter block (`---\n---\n`) is not matched; `yaml.dump` folds values over 80 chars (`width=inf`); `dump()` with empty meta writes `{}`.
- `vault`: a root-level `_cluster.md` raises; a dotted last path component (`notes/v1.2`) gets no `.md` appended; `broken_links` mixes resolved paths and raw wikilink names; path-style wikilinks (`[[10_ai/x]]`) unresolved; fences inside blockquotes and multi-line code spans not stripped; add a `bad-frontmatter`-style health kind for unreadable files.
- `index_cli`: include directory mtimes in staleness; friendly message for a missing vault path.
- `intake`: remove a partial companion on write failure; test the inbox-move branch of rollback; original/companion stems can diverge on collision; `input` absolute for non-md inbox items; share `CLUSTER_RE` instead of duplicating it; non-string scalar `tags` in raw notes; inbox duplicates re-reported every run.
- `map_json`: dedupe link edges; tolerate scalar `sources:`.
- `sources`: query string dropped from URL slugs; unbounded `resp.read()`, per-operation timeout.
- Tests: `--no-index` and exit-0-on-duplicate for `zen-intake`; KINDS order and empty-vault render for `index_md`; PK magic check / uppercase suffix / no-title HTML for `extract`.
